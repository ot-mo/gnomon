## 4. Deviations from the design, with reasons

1. **Generation made engine-independent** (not in the design, required by R6). The browser check found that Chrome
   152 generated about a third of the legacy levels differently from Node 20, and occasionally the same level twice
   differently in one session. Two causes: `props.sort(() => rand() - 0.5)` in `randomEquipment` (engines sort
   differently and call the comparator a different number of times, shifting every later draw), and `Math.hypot` in
   distance comparisons (its last bits differ between engines and between Chrome's JIT tiers). Fixes: `seededSort`
   replays Node 20's exact comparison sequence (checked against the native sort on 30,000 cases), so nothing changes in
   Node; `distance()` is exact. The second changes 2 of the 1,000 legacy levels in Node relative to the parent's Node
   behaviour (seed 41 level 18, seed 47 level 13; none of the golden seeds). The parent itself was not deterministic in
   the browser, so this is the better baseline. `check-determinism` now scans for both patterns.
2. `legacyParams(depth, runSeed = 0)` takes the run seed: the parent planned its encounters per run seed.
3. Golden (c) compares depths 2-20 (design: 2-19); level 20 matches too.
4. **Legacy level 1 has stairs up** (`hasUp` is always true, §5.5), leading to the temple. "Up" into the temple still
   uses its `returnPoint` (in front of Maren), because a map-only player at the bottom of the shaft could not cross
   the stepping stones; 0A2 turns the temple into a plan and drops `returnPoint`.
5. Event **`zone:prepare`** added (before the player is placed): the guardian gate opening from below must happen
   before the arrival point is computed, and relics resolve before you see them.
6. Zone fields `dungeonIndex` and `dungeonLevels` (from `p.index`, `p.count`): `index` is already `Zone.index()`.
7. `arrivalPoint(zone, "edge", …)` exists already (a pure function, tested on the synthetic zone); `tryWalkOff`,
   `neighbourAddr` and `prefetchNeighbours` are 0A2's, as planned.
8. Extra tools: `check-zones.mjs` (the zone core API) and `check-bot.mjs` (runs the bot under `run-all`), and
   `tests/lib/hash.js`, `tests/golden/*`. A root `package.json` (`"type": "module"`, no dependencies) so Node loads
   `src/*.js` as modules and `node tools/run-all.mjs` needs no flags.
9. The cosmetic RNG reaches `spawnMonster` as an 8th parameter `rand` (0C's `spawnCreature(…, { rng })` replaces it),
   and `stampVault` as `opts.cosmetic`.
10. `ZONE_GENERATORS` signature fixed as `(game, { wx, wy, z, key }) → Zone | null`; `ZONE_LOADER.load` is the WS9
    hook; `PATCH_OPS` is the patch-operation registry (`setFlag` and `removeUid` built in; 0C registers
    `spawnCreature`, items `placeItem`). `ZONE_RULES.keepDerived` lives in `zones.js` until `rules.js` exists (0B).
11. `game.state` starts with `{ seed, uids, zonePatches, zoneLeft }` only; the rest of §2.17 comes with its sessions.
    `zone.flags` holds `vaultHinted` and `waterHint`; second wind and the first block still set ad-hoc zone fields
    until 0B turns them into cooldowns.
12. The temple is a `"surface"` zone, so `solidFor` floats any body on its deep water (it has none: no effect).
13. HUD: the status line says "TEMPLE OF ANGLES" (was "TEMPLE"); death text "in The Temple of Angles" / "on depth n".
14. Golden (a) records more than the design's minimum (gear, pack, perks, identification as well as the derived
    numbers), all view-independent. It is recorded through the 3D inventory path with no time passing.
15. Dormant zones are never evicted from memory yet (nothing is saved until 0D2/WS9).
16. **Commit granularity**: DECISIONS.md changed during the session (`b096612`, "commit early and often"); by then the
    refactor was one working change, so it landed as one commit (`57b8aa3`). Later work follows the new rule.

## 5. Known issues

  comparison.
- `zone.monsters` and `zone.npcs` remain (0C rewrites them); `zones.js` `PATCH_OPS.removeUid` touches both and must be
  rewritten with them.
- `player.js` `inShallowWater` and the swim slowdown still test the Swimmer perk only; on a surface zone deep water now
  holds everyone up (`solidFor`) but drowning is 0B's.
- `story.js` uses `Math.atan2` for the temple's mosaic ring. Node and Chrome agree (checked); other engines are not
  promised to. The temple becomes a plan in 0A2.
- In a hidden browser pane `requestAnimationFrame` runs at about 1 frame per second and each frame's dt is capped at
  0.05 s, so the 1.2 s "DEPTH n" beat takes about 24 real seconds. Not a game bug; advance with `game.debug.step`.
